# e2e-report

Consolidate a task's latest results and export a machine-readable summary.

Shared conventions: `../_shared/conventions.md`.

**Input:** `<slug>`, with `reports/<slug>/report.json` present. If it is missing, run `/e2e run` first.

**Output:** the analysis you add to `reports/<slug>/report.md` — **written in Vietnamese** (see the language policy in conventions).

`report.csv` is **generated by the engine**, not written here. Every run emits it alongside `report.md` with the columns `TC ID, Phase, Target, Risk, Status, Scenario, Detail, Type`. Do not hand-write or reformat it: a mechanical projection of the run belongs in code, where it stays deterministic and costs nothing.

## Steps

1. Read `reports/<slug>/report.json`, plus the existing `report.md` when it already carries an analysis.

2. Update `reports/<slug>/report.md`: keep the generated result table, and write the analysis section plus links to `html/index.html` and the screenshots in `artifacts/`.

3. The only column the engine leaves blank in the CSV is **`Type`** (`feature`, `spec` or `flaky`) — classifying a failure is a judgement, not something the runner can infer. Fill it in from your analysis when the team needs it, otherwise leave it. Ids already match the plan, yaml and spec.

4. Summarise for the tester: total pass and fail counts, the **distribution across risk ratings**, and a clear split between **cases that need a developer** (genuine feature defects) and **cases that need a spec review** (`[NEEDS-SELECTOR-REVIEW]` or flaky).
